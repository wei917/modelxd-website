## 2026-08-29 — The error changed; XDuel redraws instead of breaking (pushed: 8012533)

**The Anthropic failure is no longer the monthly cap.** Probed live:

    400 {"type":"error","error":{"type":"invalid_request_error","message":
    "This organization has been disabled. An organization admin can appeal
    at https://console.anthropic.com/appeal",
    "details":{"error_code":"organization_on_hold"}}}

That is a different, more serious state than yesterday's 429 threshold, and
it does not clear on a calendar — **it needs an admin appeal at
console.anthropic.com/appeal.** That is still the real fix; everything below
is the net underneath it.

- **Both classifiers missed it**, because both were written against the Aug 28
  wording. A user picking Claude got the generic "The model failed to generate
  a response" instead of the ACCOUNT message, and house-llm's cooldown never
  armed. The wording now lives in ONE place — `ACCOUNT_LIMIT` in
  `lib/provider-errors.ts` — read by both the user-facing sanitizer and the
  fallback classifier. **A new phrasing is now one line in one file.** The
  lesson generalises: two regexes against one error message is two bugs
  waiting for the provider to rephrase.
- **XDuel redraws a dead model** (`app/api/xduel/route.ts`). The user never
  picks the models there, so a swap is a different draw, not a substitution —
  none of the reasons user-paid surfaces must NOT fall back apply. One shuffle
  yields the draw AND its reserve; a slot failing with an ACCOUNT-class error
  takes the next reserve model **from a different provider** and re-runs, once.
  A safety refusal or oversized prompt does not qualify (fails on every model
  alike). The client is untouched: `trying:` at `app/xduel/page.tsx:353` was
  dead code from an earlier worker design that already resets a slot's meta
  and text exactly as needed.
- **Attribution was the one real hazard.** `slots`, `slotPrices` and the reveal
  are built from `models` AFTER the slots settle, so without the `models[i]`
  write-back the duel row carries the DRAWN model's name over the
  REPLACEMENT's output — a vote crediting a model that never ran. Silent
  leaderboard corruption, and exactly what this whole design exists to avoid.

**Verified live** in the owner's Chrome (first duel hit it): drew
`claude-opus-5`, failed on `organization_on_hold`, redrew to
`openai/gpt-5.5-pro`; the price label ($180/1M), the reveal and the persisted

back) is cheap, and the 90s cooldown is a convenience, not a necessity.
